# React 프로젝트 구조

> “정답은 없습니다. 하지만 자주 함께 변경되는 파일은 가까이에 두세요.”\
> — React 공식 문서, [_파일 구조(FAQ)_](https://ko.legacy.reactjs.org/docs/faq-structure.html)

## React에서 파일 구조는 왜 중요한가?

React 공식 문서에서는 “React는 파일을 어떤 식으로 폴더에 분류할 것인지 강제하지 않는다”고 말합니다.\
즉, 구조는 **팀의 협업 방식과 변경 패턴**에 맞춰 자유롭게 설계할 수 있습니다.

공식 문서에서는 두 가지 주요 접근법을 소개합니다:

1. **기능(Feature) 또는 라우트(Route) 기반 구조**

```
feed/
  Feed.js
  Feed.css
  FeedStory.js
  FeedAPI.js
profile/
  Profile.js
  ProfileHeader.js
  ProfileAPI.js
```

➜ 즉, 한 기능(Feed, Profile)에 필요한 모든 파일을 **같은 폴더에 모아두는 방식**입니다.\
이게 바로 \_“코로케이션(colocation)”\_의 핵심 철학이에요.

2. **파일 유형(Type) 기반 구조**

```
components/
services/
hooks/
utils/
```

➜ 역할별(레이어별)로 분리하는 **전통적인 계층형(Layered) 구조**입니다.

공식 문서는 이렇게 결론을 내립니다:

> “결국 프로젝트가 커질수록 위의 두 방식을 섞어 쓰게 될 것입니다.\
> 자주 함께 수정되는 파일을 가까이 두는 것이 좋습니다.\
> 이것이 코로케이션(colocation) 원칙입니다.”

## Layered + Colocation 구조란?

이 가이드는 바로 그 \_“혼합형 접근법”\_을 명시적으로 적용한 형태입니다.\
즉,

- 전역적으로 공통 역할(`components`, `services`, `hooks`, `utils`)은 **Layered 구조**로 관리하고,
- 각 기능 단위(`pages/SystemBoot`, `pages/Syscall`) 내부는 **Colocation 구조**로 묶습니다.

➜ 이렇게 하면 전역 일관성과 지역 응집도를 모두 확보할 수 있습니다.

## 구조 철학 요약

| 원칙                     | 설명                                     |
| :--------------------- | :------------------------------------- |
| **Layered (계층형)**      | 역할(Role)별로 구분 — 재사용성과 명확성 확보           |
| **Colocation (근접 배치)** | 기능(Feature)별로 관련 파일을 모음 — 유지보수성 향상     |
| **Hybrid (혼합형)**       | 공용 계층은 분리하고, 기능 단위는 묶는다                |
| **변경 중심 설계**           | “함께 자주 바뀌는 파일은 함께 둔다” — React 공식 권장 원칙 |

### 실제 예시 — `/system/boot` 구조

```
pages/SystemBoot/
 ├── SystemBootPage.tsx         # 부팅 페이지 UI
 ├── hooks/useBoot.ts           # Boot 상태 관리
 ├── services/bootService.ts    # API 통신 (/system/boot)
 └── components/BootStatus.tsx  # 상태 표시 컴포넌트
```

**Colocation 효과:**\
`SystemBootPage`를 수정할 때 관련된 `useBoot`와 `bootService`를 바로 옆에서 확인 가능.\
즉, \_“작업 단위로 코드가 모여 있다”\_는 점이 생산성을 크게 높입니다.

## React 공식 문서 인용 정리

> “일반적으로 자주 함께 변경되는 파일을 함께 보관하는 것이 좋은 방법입니다.\
> 이러한 원칙을 ‘코로케이션(colocation)’이라고 부릅니다.”\
> — [React 공식 문서: 파일 구조 FAQ](https://ko.legacy.reactjs.org/docs/faq-structure.html)

> “결국에는 앞서 언급한 방법들을 섞어서 사용하게 됩니다.\
> 처음부터 ‘옳은’ 구조를 찾는 것이 중요하지 않습니다.”\
> — React Docs

## 결론

- React는 특정 폴더 구조를 강제하지 않습니다.
- **Layered + Colocation 구조**는 “규칙은 느슨하게, 응집도는 높게”라는 React 철학과 잘 맞습니다.
- 핵심은 **“함께 자주 바뀌는 코드는 가까이에 두는 것”**,\
  그리고 \*\*“역할(Role)은 명확히 분리하는 것”\*\*입니다.

### 요약

> “Layered 구조는 명확성을, Colocation 구조는 응집도를 줍니다.\
> 두 가지를 함께 쓰면, React 앱은 훨씬 유지보수하기 쉬워집니다.”
