## 파이프 및 필터 아키텍처

### 정의

- **Fiter**: 데이터를 입력받고, 필터링 등의 **실제 작업**을 수행하는 독립적인 컴포넌트
- **Pipe**: 필터와 필터 사이를 연결하여 **데이터를 전달**하는 통로

### 사용 이유?

> 관심사 분리와 재사용성 때문에 사용한다

- **복잡한 작업의 단순화**: 복잡한 작업을 한번에 구현하는 것 보다 → 독립적인 필터로 분리하여 단계적으로 처리
- **유연한 구성**: 시스템 요구사항이 바뀌어도 특정 필터를 순서를 바꿔 기능을 쉽게 수정함

### 장점

- 필터 하나를 다른 시스템에서도 쉽게 다시 사용 → **높은 재사용성**
- **유연한 확장성**: 새로운 기능을 추가하거나 기존 기능을 수정할때 시스템 전체를 수정할 필요 없음
- **유지보수 용이**: 특정 필터에 문제 생기면 해당 필터만 검사하면 되기 대문에 디버깅 쉬움

### 단점

- **데이터 형식 종속성**: 필터들이 서로 호환되는 데이터 포맷을 사용해야 해서 데이터 인터페이스 정의가 매우 중요
- **에러 핸들링의 어려움**: 어디 필터에서 오류가 발생한지는 찾을 수 있지만 에러를 추적하거나 흐름을 제어하는 중앙 집중적 제어가 어렵다.

## 트랜잭션 처리 시스템

### 정의

'트랜잭션'은 데이터베이스의 상태를 변경하는 하나 이상의 연산으로 구성된 논리적인 작업 단위이며, **ACID(Atomicity, Consistency, Isolation, Durability)** 속성을 보장해야 한다!

- **원자성(Atomicity):** 트랜잭션 내의 모든 연산은 완전히 성공하거나 완전히 실패해야 한다. (All or Nothing)
- **일관성(Consistency):** 트랜잭션이 실행된 후에도 데이터베이스의 제약 조건과 규칙이 일관되게 유지되어야 함.
- **고립성(Isolation):** 동시에 실행되는 여러 트랜잭션은 서로에게 영향을 주지 않고 독립적으로 실행되는 것처럼 보여야 함.
- **지속성(Durability):** 트랜잭션이 성공적으로 완료되면, 그 결과는 시스템 오류나 전원 손실에도 불구하고 영구적으로 반영되어야 함.

### 사용 이유 

**'데이터의 신뢰성(Reliability)'**과 **'업무 자동화'** 때문

- **데이터 무결성 보장:** 돈이 이체되는데 내 계좌에선 나갔지만 상대방 계좌엔 들어오지 않는 상황(중간 단계에서 멈추는 현상)을 원천 차단해야 하기 때문
- **실시간 처리:** 대량의 데이터를 지연 없이 즉각적으로 반영해야 하는 운영 시스템에서 효율적인 처리를 가능하게 함.
- **오류 복구:** 시스템 장애가 발생하더라도 로그를 통해 트랜잭션 수행 시점으로 안전하게 되돌릴 수 있음.

### 장점

- **데이터 신뢰성:** ACID 원칙을 통해 데이터의 손실이나 불일치를 방지
- **운영 효율성:** 반복적이고 방대한 데이터를 자동화하여 처리 속도를 극대화
- **동시성 제어:** 여러 사용자가 동시에 데이터를 수정해도 데이터 충돌을 막고 안전하게 처리

### 단점

- **복잡한 구현**: ACID를 보장해야해서 LOCK 매커니즘 시스템 설계가 복잡함
- **성능 부하**: 데이터 무결성 검증하는 과정에서 연산 비용 필요
